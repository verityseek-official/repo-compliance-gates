# Security Policy

Security reports may include scanner bypasses, unintended secret disclosure, path escapes, unsafe command execution, or CI behavior that exposes credentials.

Do not post exploit details, real credentials, private keys, tokens, cookies, or sensitive repository content in a public issue. Use GitHub's private vulnerability reporting for this repository when available. If a private channel is unavailable, open a minimal public issue requesting private contact without including sensitive details.

If a real credential may have been exposed, revoke or rotate it with the provider immediately. Do not send the credential to the maintainers, even through a private report.

Include the affected version, operating system and Node.js version, a minimal synthetic reproduction, expected behavior, and observed impact. Maintainers will validate the report and coordinate remediation and disclosure when appropriate.

Only the latest released version is actively supported. Ordinary bugs and policy proposals that do not expose sensitive details may use public issues.
